# Task 1 — Settings file reader with defaults

Target: claude

## Goal
Implement the settings half of feature `server-access`: a pure-Lua INI
reader and a `settings.load()` that returns a complete settings value from
`config.ini` in the tool's local data folder, falling back to the default for
every missing or invalid key. Every server-touching feature reads its
address, TLS level and switches through this.

## Acceptance criteria
- An INI parser in `rpm_core.lua` (no `reaper.*` calls) reads sections and
  `key=value` pairs, ignores `;` and `#` comments (full-line and trailing),
  trims whitespace, and tolerates a UTF-8 BOM and CRLF line endings.
- `settings.load()` returns every key of the documented schema:
  `server.url`, `server.user`, `server.tls` (`required` | `try` | `off`,
  default `required`), `server.insecure` (default `0`), `install.vst2_dir`,
  `check.auto` (default `1`), `check.notify_unknown` (default `1`).
- An invalid value (unknown TLS level, non-0/1 switch) falls back to its
  default; a missing file yields all defaults; it never raises.
- `server.url` is returned with a trailing `/` when non-empty.
- An INI writer exists for `setup-action` to save settings without losing
  keys it does not edit.

## Decisions
- The INI reader and writer live in `rpm_core.lua`, per the two-module
  layout of `technical-direction.md`, so they stay usable outside REAPER.
- `server.user` lives in the settings file and the password never does
  (feature document, Data and state).
