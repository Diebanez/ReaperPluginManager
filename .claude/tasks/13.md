# Task 13 — Setup dialog, validation and saving

Target: claude

## Goal
Implement the first half of feature `setup-action`: the setup action's
guard, its five-field dialog prefilled with the current values, validation,
and saving the settings and the server credential.

## Acceptance criteria
- REAPER without `EnumInstalledFX` → "REAPER 7 or later is required";
  Linux → a message that the tool does nothing there, then exit.
- One `GetUserInputs` dialog with URL, user, password (caption starting
  with `*` to mask it), TLS level and automatic check, using
  `separator=\n`; current values proposed, password field empty.
- URL without a scheme is rejected; a valid URL gains a trailing `/`; an
  invalid TLS value becomes `required`; the automatic-check field accepts
  yes/no forms and defaults to on; a password with whitespace is rejected.
  A rejection reopens the dialog with the other values kept.
- Saving writes the settings file without losing keys the dialog does not
  edit, and the password through the credential store; empty user deletes
  the stored secret; empty password with the same user keeps the stored
  one.
- A cancelled dialog changes nothing.
