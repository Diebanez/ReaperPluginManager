# Task 2 — Server credential store and short-lived credentials file

Target: claude

## Goal
Implement the credential half of feature `server-access`: the server
password lives only in the OS secret store (Windows DPAPI current-user, macOS
Keychain), is read at most once per REAPER session, and is materialized into
a `netrc`-format credentials file only for the duration of a transfer, so it
never appears on a command line or in a plain file at rest.

## Acceptance criteria
- `credentials.get()` returns user and password, `nil` password for an empty
  user (anonymous), or an error naming the store; the password is cached in
  memory for the session after the first read.
- Writing and deleting the stored password are available to `setup-action`;
  deleting is what an empty user triggers.
- Windows back end: a PowerShell 5.1 helper script encrypts/decrypts with
  .NET `ProtectedData` (CurrentUser); the secret is passed by temporary file
  or stdin, never as an argument, and any temporary file is deleted.
- macOS back end: a bash helper using the `security` tool, keyed by server
  host and user, with the password never on a command line.
- The credentials file (`machine`, `login`, `password`) is written into the
  local data folder with owner-only permissions on macOS, returned as a path,
  and removed by the caller's release; stale credentials files left by a
  crash are swept when the tool starts.
- Passwords containing whitespace are rejected by a validation function
  `setup-action` can call (the `netrc` format cannot hold them).

## Decisions
- One server account per machine (feature document, Non-goals); keys are
  host + user.
- The secret-store helpers are separate scripts under `helpers/`, reused by
  `licence-activation` for saved serials (its document names these back
  ends).
