# Task 3 — curl transfer layer

Target: claude

## Goal
Implement the transfer half of feature `server-access`: one place that turns
settings and credentials into `curl` invocations for download, blocking and
background upload, safe replace, rename and delete, plus the option set
handed to the install helpers.

## Acceptance criteria
- Common options built from settings: `--fail --silent --show-error
  --location --ftp-pasv`, a timeout, `--ssl-reqd` for `tls=required`,
  `--ssl` for `try`, `--insecure` when `insecure=1`, `--netrc-file` when a
  credentials file exists.
- `transfer.download`, `transfer.upload`, `transfer.replace`,
  `transfer.delete` return `ok, err`; `err` is a one-line reason built from
  curl's exit code and stderr, never containing the password.
- `transfer.upload_async` starts curl without waiting and returns a handle
  whose `poll()` reports `running` / `done` / `failed` with bytes done and
  total, read from a small status file the background process writes.
- Safe replace uploads `<name>.uploading` then renames over `<name>`:
  `RNFR`/`RNTO` over FTP/FTPS, WebDAV `MOVE` over HTTPS; delete is `DELE` /
  WebDAV `DELETE`.
- `file://` servers: download, upload, rename and delete are a copy, copy,
  move and removal on the filesystem.
- `transfer.helper_options()` returns the credentials-file path (only when
  one exists), TLS level and insecure flag.
- Windows launches through `reaper.ExecProcess`, macOS through `io.popen` /
  `os.execute`; credentials files are released after each blocking transfer.

## Decisions
- Background upload uses its own status file rather than the install
  helper's protocol: uploads are the maintainer's, not part of an install
  run.
