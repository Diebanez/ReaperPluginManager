# Task 37 — Publish the catalogue draft

Target: claude

## Goal
Implement feature `catalogue-publish`: send the maintainer's draft to the
server so members only ever see a complete, consistent catalogue — check for
server-side changes, upload new installers in the background, replace the
catalogue safely, then delete installer files no longer referenced.

## Acceptance criteria
- Change check: re-fetches the server catalogue; when it differs from the
  draft's base, warns and asks whether to publish over it or stop.
- Upload phase: each attached local installer not yet uploaded goes to its
  server path through `transfer.upload_async`, one at a time, with per-file
  progress in the editor window and REAPER usable; uploaded state is kept in
  the draft so a retried publish resumes; any failure stops before the
  catalogue is touched and names the file.
- Catalogue phase: encodes the draft and replaces `manifest.json` with
  `transfer.replace`; the new catalogue becomes the local cache.
- Cleanup phase: deletes every installer file the base referenced and the
  new catalogue does not; a failed delete is reported as an orphan and the
  publish still counts as done.
- Finish: clears the draft and shows a summary of uploads, the replace and
  deletions. A read-only account fails with the server's error and changes
  nothing.
