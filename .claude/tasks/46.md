# Task 46 — Windows helper script installers

Target: claude

## Goal
Add `script` entries to feature `install-helper-windows`: unpack the
verified zip and run its `install.ps1` with Windows PowerShell 5.1 inside the
already elevated helper, with the `RPM_*` variables of the helper contract,
so a plugin that no silent installer or plain plugin files can install (The
Cue: a VST3 plus a data folder beside it) installs like any other entry.

## Acceptance criteria
- `script` is an accepted type; any other type outside `exe`, `msi`, `zip`,
  `script` still fails with "installer type not supported on Windows".
- After download and verify as for any entry, under `ITEM <id> install`, the
  zip is unpacked with .NET `ZipFile.ExtractToDirectory` into the entry's
  work folder; no `install.ps1` at the zip's root →
  `FAIL <id> no install.ps1 in the archive`.
- `install.ps1` runs as `powershell.exe -NoProfile -ExecutionPolicy Bypass
  -File install.ps1` with the unpacked folder as working directory, in the
  helper's own elevated process tree (no second UAC prompt), waiting with no
  time limit.
- The script's environment carries `RPM_PAYLOAD_DIR` (the unpacked folder),
  `RPM_VST3_DIR`, `RPM_CLAP_DIR` and `RPM_VST2_DIR` from Vst3Dir, ClapDir and
  Vst2Dir, `RPM_VST2_DIR` empty when no VST2 folder is set; the variables do
  not leak into the next entry.
- Exit code 0 → `OK <id>`, `work/<id>` deleted. Any other exit code (3010
  included) → `FAIL <id>` with the script's last non-empty output line
  (stdout and stderr, made one line), or `install script exited with code
  <n>` when it printed nothing; `work/<id>` kept.
- The call follows the helper's pitfalls for native programs: error
  preference relaxed around it, the exit code read from `$LASTEXITCODE`, so
  a script writing to stderr is not turned into a helper error.
- `rpm-install.ps1` stays Windows PowerShell 5.1 and ASCII-only, and its
  header comment lists `script` among the types.

## Decisions
- Only exit code 0 counts as success for a script: the contract says "any
  other exit code" fails, so the `exe`/`msi` 3010 reboot code does not apply.
