# Task 48 — macOS helper script installers in the privileged phase

Target: claude

## Goal
Add `script` entries to feature `install-helper-macos`: unpack the verified
zip, queue it beside the packages, and run its `install.sh` in the same
administrator-privileged phase, under the one password prompt of the run,
with the `RPM_*` variables of the helper contract, so a plugin that no
installer or plain bundle copy can install (The Cue: a VST3 plus a data
folder beside it) installs like any other entry.

## Acceptance criteria
- `script` is an accepted type; any other type outside `zip`, `dmg`, `pkg`,
  `script` still fails with "installer type not supported on macOS".
- Under `ITEM <id> install`, the zip is unpacked with `ditto -x -k` (the
  `unzip` fallback when `ditto` is missing) into the entry's work folder; no
  `install.sh` at the zip's root → `FAIL <id> no install.sh in the archive`;
  otherwise the entry is queued, keeping its kind beside the queued packages
  (bash 3.2 indexed arrays only).
- The privileged phase's generated script runs, per queued entry in queue
  order, `/usr/sbin/installer -pkg … -target /` for a package (unchanged) or
  `/bin/bash install.sh` from the unpacked folder for a script entry, with
  `RPM_PAYLOAD_DIR` (the unpacked folder), `RPM_VST3_DIR`, `RPM_CLAP_DIR`,
  `RPM_VST2_DIR` and `RPM_AU_DIR` set from the plugins root (`VST3/`,
  `CLAP/`, `VST/`, `Components/`), no time limit.
- A script entry exiting 0 writes `OK <id>`; any other exit code writes
  `FAIL <id>` with the script's last non-empty output line (stdout and
  stderr, made one line), or `install script exited with code <n>` when it
  printed nothing.
- The whole phase still runs once through `osascript … with administrator
  privileges`: one password prompt for packages and scripts together, and
  none when nothing is queued. A cancelled prompt →
  `FAIL <id> administrator password not entered` for every queued entry
  without an outcome; `work/<id>` is deleted after `OK` and kept after
  `FAIL`, as for packages.
- `rpm-install.sh` stays bash 3.2 (no associative arrays, `mapfile` or
  `${var,,}`), and its header comment lists `script` among the types.

## Decisions
- The `RPM_*` paths are computed by the helper as the member and embedded in
  the generated script, so `~` resolves to the member's plugin folders even
  though the script runs as root.
