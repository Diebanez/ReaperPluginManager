# Task 48 — macOS helper script installers run as the member

Target: claude

## Goal
Add `script` entries to feature `install-helper-macos`: unpack the verified
zip and run its `install.sh` as the member, in the helper's unprivileged
pass beside zip routing and never inside the administrator prompt, with the
`RPM_*` variables of the helper contract set to the folders under the
member's plugins root, so a plugin that no installer or plain bundle copy
can install (The Cue: a VST3 plus a data folder beside it) installs like any
other entry without asking for a password.

## Acceptance criteria
- `script` is an accepted type; any other type outside `zip`, `dmg`, `pkg`,
  `script` still fails with "installer type not supported on macOS".
- Under `ITEM <id> install`, the zip is unpacked with `ditto -x -k` (the
  `unzip` fallback when `ditto` is missing) into the entry's work folder; no
  `install.sh` at the zip's root → `FAIL <id> no install.sh in the archive`.
- Otherwise `/bin/bash install.sh` runs at once from the unpacked folder, as
  the member running the helper (no `osascript`, no `sudo`), with
  `RPM_PAYLOAD_DIR` (the unpacked folder), `RPM_VST3_DIR`, `RPM_CLAP_DIR`,
  `RPM_VST2_DIR` and `RPM_AU_DIR` set to the plugins root's `VST3/`,
  `CLAP/`, `VST/` and `Components/` folders, and no time limit.
- Exit code 0 → `OK <id>`; any other exit code → `FAIL <id>` with the
  script's last non-empty output line (stdout and stderr, made one line),
  or `install script exited with code <n>` when it printed nothing.
  `work/<id>` is deleted after `OK` and kept after `FAIL`, as for every
  entry.
- A script entry is never queued for the privileged phase: a job whose
  entries are only zips and scripts shows no password prompt, and the
  privileged phase still runs only the queued packages.
- `rpm-install.sh` stays bash 3.2 (no associative arrays, `mapfile` or
  `${var,,}`), and its header comment lists `script` among the types and
  says scripts run as the member.

## Decisions
- The script runs at its own turn in the job's order, inside `install_one`,
  rather than in a second pass after the loop: the feature document places
  it in the same unprivileged pass as zip routing, and this keeps the
  per-entry status lines in job order.
