# Task 49 — Update documentation for feature `install-helper-macos`

Target: claude

## Goal
Feature `install-helper-macos` installs `script` entries by running their
`install.sh` as the member (task 48), and the maintainer's description of
macOS installers is now out of date: bring `server/README.md` § Installers
on macOS in line with the shipped behavior.

## Acceptance criteria
- § Installers on macOS lists `script` beside `zip`, `dmg` and `pkg`: the
  zip is unpacked and its `install.sh` runs with bash as the member, with
  the member's own rights and no password; a zip with no `install.sh` at its
  root fails with "no install.sh in the archive"; only exit code 0 counts as
  success.
- It states that a macOS install script can write only where the member
  can — the member's `~/Library/Audio/Plug-Ins` folders, not system
  locations such as `/Library` or `/Applications` — so a plugin that needs
  those ships its vendor `pkg` instead.
- The sentence naming the types that fail as unsupported on macOS matches
  the four supported types.
- § One password for packages states that only packages need the password:
  script entries install without it, so a run whose entries are only zips
  and scripts asks for no password.
- The environment variables, the failure message taken from the script's
  output, and the worked example are not written here.

## Decisions
- This task owns only § Installers on macOS and § One password for
  packages. The script-installer section of `server/README.md` (building
  the zip, the `RPM_*` variables, exit codes, the worked example) belongs to
  feature `catalogue-editor`'s documentation task, which writes the whole
  change's cross-platform passage once.
