# Task 52 — Script installers and the unmanaged mark in the editor

Target: claude

## Goal
Bring the `script` installer type into feature `catalogue-editor`: the entry
form offers it on Windows, on macOS and for a shared package, without the
silent-install arguments and destination that do not apply to it, the
editor's own validation accepts it, and the entry list marks every entry
with a `script` installer on either platform "unmanaged installer", so the
maintainer sees which entries members will be warned about.

## Acceptance criteria
- The entry form's Type list offers `script` in the Windows, macOS and
  shared-package slots, with a label saying it is a zip carrying an install
  script; "From the file extension" never yields `script`.
- For a `script` installer the form does not offer "Silent-install
  arguments" or "Destination"; attaching the zip, its checksum and its
  server path work as for any installer.
- The editor's validation accepts `script` on both platforms and in a
  shared package, and still derives a missing type only from `exe`, `msi`,
  `zip` / `pkg`, `dmg`, `zip` extensions, its problem message listing the
  types each slot allows.
- The entry list shows "unmanaged installer" on every entry for which
  `core.catalogue.unmanaged(entry, "windows")` or
  `core.catalogue.unmanaged(entry, "macos")` is true, beside the existing
  added/changed/removed marks and validation problems.
- An imported draft entry with a `script` installer keeps it, its server
  path and its mark.
