# Task 53 — Update documentation for feature `catalogue-editor`

Target: claude

## Goal
Feature `catalogue-editor` offers the `script` installer type and marks
unmanaged installers (task 52), and the server setup guide does not yet tell
the maintainer how to curate or build a script installer: bring
`server/README.md` in line with the shipped behavior of the editor, and
write, once for the whole script-installer change, the guide's section on
building a script installer.

## Acceptance criteria
- § The local draft (the entry list) states that an entry with a `script`
  installer on either platform is marked "unmanaged installer", and that
  members are warned before such an entry installs.
- § The entry form states that `script` is offered on Windows, on macOS
  and for a shared package, and that silent-install arguments and
  destination do not apply to it.
- A new section on script installers, beside the two platform installer
  sections, tells the maintainer when to use one (a plugin no silent
  installer or plain plugin files can install), how to build the zip
  (`install.ps1` for Windows, `install.sh` for macOS, at the zip's root,
  with the files they install; both scripts in one zip for a shared
  package), the variables the script receives (`RPM_PAYLOAD_DIR`,
  `RPM_VST3_DIR`, `RPM_CLAP_DIR`, `RPM_VST2_DIR` — empty when the member
  set no VST2 folder — and, on macOS, `RPM_AU_DIR`), that it runs with
  administrator rights and no time limit, and its exit codes: 0 is success,
  anything else fails with the script's last non-empty output line, or
  "install script exited with code <n>" when it printed nothing.
- The section gives a worked example for a plugin plus a data folder that
  must sit beside it in the VST3 folder, Polarity Audio's The Cue: the zip
  layout, a minimal `install.ps1` (Windows PowerShell 5.1) and `install.sh`
  (bash 3.2) that copy `The Cue.vst3` and `The Cue.instruments` into the
  VST3 folder replacing any earlier copy, and the catalogue entry, matching
  the `script` entry of `server/manifest.example.json`.
- It advises trying a script installer by hand on each platform before
  publishing, and that it is an unmanaged installer members are warned
  about.
- The passages written by the other documentation tasks of this change —
  § The catalogue format, § Installers on Windows, § Installers on macOS,
  § One password for packages, and `README.md` — are linked to, not
  restated.

## Decisions
- This task writes the cross-platform script-installer section of
  `server/README.md` for the whole change, since it is the last planned and
  the section needs both helpers and the catalogue example to exist; its
  Preconditions therefore also name tasks 44–49, beyond this run's own
  task.
