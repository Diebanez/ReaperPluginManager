# Task 60 — Update documentation for feature `catalogue-browser`

Target: claude

## Goal
Feature `catalogue-browser` adds a fifth action, the catalogue browser
(tasks 54–59), and changes contracts other features document: presence
detection and the platform installer lookup become shared functions, the
unmanaged confirmation and the list primitives are shared, the install
running state holds across scripts, `start` takes a no-reopen option, and
setup registers five actions. Bring the member guide, the project
instructions and the domain passages that state the old design in line with
the shipped behaviour.

## Acceptance criteria
- `README.md` describes the new action for members: a section on browsing
  the catalogue (*Script: RPM_Browse.lua*: the list and each plugin's state,
  the search field, ticking and installing, the unmanaged-installer prompt,
  the refusal while an install runs, the cached-catalogue banner); *What
  Setup does* lists five actions; *Restart and reopen* says a run started
  from the browser reopens no project; *Installing plugins* covers installs
  started from the browser as well as from the summary.
- `CLAUDE.md` § Layout names the five REAPER actions, `RPM_Browse.lua`
  among them.
- `.claude/domain/features/plugin-installation.md` states the agreed design
  change — `start(entries, opts)` with `{ reopen = false }` (no reopen
  record, restart message without "this project reopens"), the cross-script
  `is_running()` through the non-persistent ExtState
  `ReaperPluginManager/install_heartbeat`, `start` refusing on it, and
  `catalogue-browser` as a caller — in every passage that stated the old
  one (§ Purpose, § Scope and non-goals, § Architecture Completion, § Data
  and state, § Interfaces and contracts, § Dependencies). Nothing else in
  the document changes.
- `.claude/domain/features/project-watcher.md` states the agreed design
  change — the unmanaged confirmation is the shared
  `confirm_unmanaged(items, platform, title)` the summary window and the
  catalogue browser both call, the list primitives are shared with the
  browser window, and the pause during an install covers runs any script
  started — in every passage that stated the old one (§ Architecture
  Watcher loop, Summary window, Install hand-off; § Interfaces and
  contracts). Nothing else in the document changes.
- `.claude/domain/features/plugin-detection.md` states the agreed design
  change — presence is the pure `present_entries(installed, lookup) → set`,
  called by the classifier and the catalogue browser, and the classifier's
  `spec` comes from `catalogue.installer` — in every passage that stated the
  old one (§ Architecture Catalogue association and Classifier, § Interfaces
  and contracts). Nothing else in the document changes.
- `.claude/domain/features/plugin-catalogue.md` states the agreed design
  change — `catalogue.installer(entry, platform) → installer | nil` beside
  `unmanaged`, and `catalogue-browser` among the readers of both — in every
  passage that stated the old one (§ Interfaces and contracts). Nothing else
  in the document changes.
- `.claude/domain/features/setup-action.md` states the agreed design change
  — setup registers five action scripts, "Script: RPM_Browse.lua" among
  them — in every passage that stated the old one (§ Architecture Action
  registration). Nothing else in the document changes.
- `.claude/domain/technical-direction.md` states the agreed design change —
  the five action scripts (browse catalogue added) and the install
  heartbeat among the ExtStates — in every passage that stated the old one
  (§ Topology / architecture, § Stack's list of what the Lua side covers,
  § Inter-component protocols). Nothing else in the document changes.

## Decisions
- **Design change agreed (user decision, `2026-10-23`):** the user approved
  the new action and the shared contracts named in
  `catalogue-browser.md` § Shared with existing features when the feature
  was designed; the passages above are its consequences:
  plugin-installation's `start` gains the no-reopen option and
  `is_running()` holds across scripts through the install heartbeat;
  project-watcher's unmanaged confirmation and list primitives become
  shared with the browser, and its install pause covers every script's run;
  plugin-detection's presence step becomes `present_entries` and its
  installer lookup `catalogue.installer`; plugin-catalogue gains
  `catalogue.installer`; setup-action registers five actions;
  technical-direction's topology lists five action scripts and the install
  heartbeat. `.claude/domain/features/*.md` are normally `/architect`'s and
  `technical-direction.md` `/product-design`'s; this task updates them for
  exactly this and for nothing else. A further design decision met at
  implementation time is not covered: leave that passage untouched and name
  it under *Follow-ups* as a precise follow-up.
- `product-design.md` already describes the catalogue browser and is not
  touched; `catalogue-browser.md` is the design itself and is not touched.
- `server/README.md` is not touched: the browser is member-facing and
  changes nothing on the server.
