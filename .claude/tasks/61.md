# Task 61 — Guided plugin scan after an install run

Target: claude

## Goal
Implement the guided scan of feature `plugin-installation`: when an install
run installed anything, after licence activation, RPM opens REAPER's FX
browser, asks the member to choose "Scan for new plugins", watches REAPER's
installed plugins until every installed entry is detected, and then offers to
reload the project the run started from, so the new plugins work without a
restart. The restart message and the reopen record stay as the fallback when
the scan does not detect them. REAPER has no action or API that runs the scan
itself.

## Acceptance criteria
- After the walk-through closes, a run that installed anything writes the
  reopen record (project runs only, as today) and opens the guided-scan
  `gfx` window instead of the restart message box; a run with nothing
  installed ends after the summary as today.
- On opening, the FX browser is shown with the main action "View: Show FX
  browser window", run only when `reaper.GetToggleCommandState` reports it
  off, since running it on an open browser closes it.
- The window tells the member to choose "Scan for new plugins" in the FX
  browser (its FX menu, or a right-click on its filter field) and lists each
  installed plugin as "waiting for the scan" or "detected", with a note that
  closing the window falls back to a restart.
- About once a second it re-reads `M.check.installed()` and marks an entry
  detected when `core.present_entries` finds it through a match index built
  from the run's installed entries only (`core.catalogue.index` over
  `{ plugins = installed entries }`).
- Every installed entry detected → the reopen record is deleted and the
  window says the new plugins are ready to use. A project run offers "Reload
  project" and "Not now"; a run started with `reopen = false` offers "Close".
  The run ends on the member's answer; "Reload project" then opens the
  recorded project with `reaper.Main_openProject` when its file still
  exists, after the run has ended, so the watcher checks it as on any
  opening.
- The member closes the window (close box or Escape), or 3 minutes pass with
  an entry still waiting → the window closes, the existing restart message
  (`RESTART_MESSAGE`, or `RESTART_MESSAGE_NO_REOPEN` for a run with no
  project) is shown, the reopen record stays, and the run ends.
- `M.install.is_running()` stays true, and the install heartbeat keeps
  beating, until the guided scan has ended, so no second run starts while it
  waits.
- An error in a scan-window cycle goes to the REAPER console, closes the
  window and ends the run with the reopen record kept, as the progress
  window's error path does.
- The comments describing the run's end — the install section header,
  `hand_off`, `M.install.start`, `M.install.is_running` and
  `M.activation.after_install`'s `on_close` — describe the guided scan.

## Decisions
- Settled here (the design leaves them to implementation): the window title
  "ReaperPluginManager - Detecting new plugins", a 1 s poll interval, and
  detection through a match index of the installed entries alone, so an
  entry already present before the run cannot be mistaken for another.
- The reload happens after the run ends rather than inside it, so the
  watcher, paused while a run is in progress, checks the reloaded project
  and reports any plugin that failed to install.
- The FX browser's command id is resolved at implementation time from
  REAPER's action list ("View: Show FX browser window"); if it differs
  between Windows and macOS, use `reaper.NamedCommandLookup` or the id both
  share.
