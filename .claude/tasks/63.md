# Task 63 — Restart helpers

Target: claude

## Goal
Add the restart helper of feature `plugin-installation`: a small detached
platform script that waits for REAPER to quit and then starts it again, so
the restart offer after an install can restart REAPER on the member's
confirmation (REAPER detects new plugins only when it starts).

## Acceptance criteria
- `Scripts/ReaperPluginManager/helpers/rpm-restart.ps1` (Windows PowerShell
  5.1, ASCII only) takes `-Exe <path to reaper.exe>`. Every 0.5 s it checks
  for a running process whose executable path equals `-Exe`
  (case-insensitive); once none is left it starts `-Exe` again
  (`Start-Process`, working folder its own folder) and exits. When one is
  still running after 60 s it exits without starting anything. It writes no
  output and no file.
- `Scripts/ReaperPluginManager/helpers/rpm-restart.sh` (bash 3.2) takes the
  REAPER app bundle path as its one argument, waits the same way for every
  process running an executable inside that bundle to end (`pgrep -f` on
  `<bundle>/Contents/MacOS/`, or `ps`), then runs `open "<bundle>"`; same
  0.5 s poll and 60 s limit, no output.
- Both scripts are listed in `RPM_Setup.lua`'s `@provides` (not `[main]`),
  so ReaPack ships them; the `@version` is not bumped here.
- `CLAUDE.md`'s Layout names the restart helpers beside the install
  helpers.

## Decisions
- The process match is by executable path, not by name, so a second REAPER
  installation (a portable one) running at the same time does not block or
  trigger the restart.
- The helpers take no PID: a ReaScript cannot read REAPER's own process id.
