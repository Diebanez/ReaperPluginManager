# Task 64 — Restart offer and reopening every open project

Target: claude

## Goal
Replace the guided plugin scan of feature `plugin-installation` with the
restart offer: when an install run installed anything, after licence
activation, a Yes/No prompt offers to restart REAPER now. On Yes RPM records
every open project, launches the restart helper (task 63) and quits REAPER;
after the restart the watcher reopens those projects. On No the member gets
the restart reminder, as before the guided scan existed.

## Acceptance criteria
- The guided scan is removed from `rpm_reaper.lua`: its window, the FX
  browser opening, the detection polling and their constants and helpers
  are gone, and no comment mentions them.
- After the walk-through closes, a run that installed anything shows a
  Yes/No message box (`ShowMessageBox` type 4, title the install window's):
  "<N> plugin(s) installed. REAPER detects new plugins only when it starts.
  Restart REAPER now? The projects open now reopen after the restart." A
  run with nothing installed ends after the summary.
- **Yes:** the reopen record (`ReaperPluginManager/reopen`, persistent) is
  written as one path per line — every open project tab that has a file, in
  tab order, with the active one moved last; the run ends (heartbeat
  deleted); the restart helper is launched without waiting, with REAPER's
  executable (Windows: `GetExePath()` + `\reaper.exe`, through hidden
  PowerShell like the install helper; macOS: the `.app` bundle derived from
  `GetExePath()`, through `nohup /bin/bash … >/dev/null 2>&1 &`); then the
  main action "File: Quit REAPER" (40004) runs. A helper that cannot be
  launched → a message saying REAPER could not be restarted and asking the
  member to restart it, REAPER does not quit, and the record stays.
- **No:** the existing restart message is shown (`RESTART_MESSAGE`, or
  `RESTART_MESSAGE_NO_REOPEN` for a run started with `reopen = false`); a
  project run records only its own project, a `reopen = false` run records
  nothing.
- `M.install.reopen_after_restart()` reads a record of one or more lines:
  after its 2 s wait it deletes the record and opens each path in order
  whose file exists and that is not already open in a tab — the first into
  the current tab when that tab has no file and no changes
  (`IsProjectDirty`), the others into a new tab ("File: New project tab",
  40859, then `Main_openProject`). It ends with the tab of the record's last
  path selected (`SelectProjectInstance`) when that project is open. A
  one-line record behaves as before.
- `is_running()` covers the run until the restart offer is answered.
- The comments describing the run's end (install section header,
  `hand_off`, `M.install.start`, `M.install.is_running`,
  `M.activation.after_install`) describe the restart offer.
- The 200-local limit of the module's top level is respected (the restart
  offer's helpers may share a `do` block).

## Decisions
- Settled here (the design leaves them to implementation): "Quit REAPER"
  is 40004 and "New project tab" 40859; verify both in REAPER's action list
  wording in a comment beside them.
- The record is written before the quit, so a member who cancels REAPER's
  save prompt keeps it for the next start rather than losing it.
