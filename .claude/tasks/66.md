# Task 66 — Import draft attaches local installers named by `source`

Target: claude

## Goal
Feature `catalogue-editor` lets a draft entry file name a local installer —
`source`, an absolute path on this machine, in place of `file` and `sha256`,
beside its `type`, `args` and `dest` — and Import draft attaches it exactly
as a file picked with **Attach file...** is, so the maintainer no longer
attaches installers by hand after importing a draft. An installer naming
`file` keeps working as today: kept at its server path and never uploaded.

## Acceptance criteria
- `core.editor.read_draft_entry` accepts a draft whose installers name
  either `file` or `source`; a `source` installer keeps its `source`,
  `type`, `args` and `dest`, its `type` checked against the platform as a
  catalogue installer's is (or left to the source's extension when absent);
  an installer naming neither is refused with the reason, as an invalid
  entry is. A draft naming only `file` installers reads exactly as before.
- On import (added or merged), each `source` installer is attached as
  `attach` does: its size and SHA-256 computed, its server path assigned in
  the entry's folder (`<id>/windows/<name>`, `<id>/macos/<name>`, or
  `<id>/<name>` when the same `source` stands under both `installers` keys,
  a shared package), and recorded in the draft's files so Publish uploads
  it; `type`, `args` and `dest` come from the draft entry file.
- Only `file` installers are marked as already on the server.
- A `source` that does not exist or cannot be read at import still imports
  the entry; that installer is flagged as missing on its entry exactly as a
  vanished local installer is, and the status line names it. A checksum
  that cannot be computed stays empty and the status line says so, as for
  **Attach file...**.
- The `sha256` of a `source` installer is the one computed at import; a
  `sha256` in the draft entry file beside `source` is ignored.
- No `source` key reaches the saved draft's catalogue or the published
  catalogue: the local path lives only in the draft's files record, as for
  an attached file.
- `rpm_core.lua` still makes no `reaper.*` call.

## Decisions
- **Shared package from one `source`.** The same `source` under both keys is
  a package shared by both platforms, mirroring how a catalogue names a
  shared package with the same `file` under both keys.
- **The import computes the checksum.** A draft's checksum for a local file
  could be stale by import time; the editor's own computation is the one
  the catalogue carries.
