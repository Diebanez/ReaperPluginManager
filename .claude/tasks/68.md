# Task 68 — Catalogue assistant takes local installers and drafts them as `source`

Target: claude

## Goal
Feature `catalogue-assistant` accepts the plugin's installers as server
paths or as local files on the maintainer's machine, inspects a local one
where it is, and writes it into the draft entry file as `source` with its
type, silent switches and `dest`, so the catalogue editor's Import draft
(task 66) attaches it and the maintainer attaches nothing by hand.

## Acceptance criteria
- `SKILL.md` § Inputs: each installer is a server path, relative to the
  server root exactly as a catalogue `file` names it, or a local file given
  by an absolute path (a drive-letter or UNC path on Windows, a path
  starting with `/` or `~` on macOS); an absolute path is always local, a
  relative one always a server path. The frontmatter `description` and
  `argument-hint` say so.
- `fetch-installer.sh` gains an `inspect "<local path>" [...]` subcommand
  that prints, per file, the same tab-separated `OK` line as `fetch` (the
  local path in both path columns, size, SHA-256, kind, generator) or
  `FAIL <path> <reason>` for a file that is missing or unreadable; it reads
  no settings and no credentials, creates no temporary folder, and never
  copies or changes the file. Its usage text and header name it.
- `SKILL.md` § Boundaries: installers come from the group's server or the
  maintainer's own local files named at invocation, never from a vendor
  site; a local installer is read in place, never copied, changed, run or
  mounted for writing.
- `SKILL.md` Step 1 inspects local installers with `inspect` and server ones
  with `fetch`, the type, platform, generator and contents rules applying to
  both; only a `fetch` folder is cleaned afterwards.
- `SKILL.md` Steps 4–5: a local installer is written as `source` (its
  absolute path) with `type`, `args` (Windows) and `dest` when needed, and
  no `file` or `sha256`; a local shared package is the same object under
  both `installers` keys; a server installer is written exactly as before.
  The key-order rule names `source` in the tool's encoder order.
- `SKILL.md` Step 5's validation snippet validates the draft with
  `core.editor.read_draft_entry`, which accepts `source` installers.
- `SKILL.md` Step 6: the report lists each local installer's `source` and
  SHA-256 (the editor recomputes it at import), and the next step says
  Import draft attaches the installers, leaving only review, testing and
  Publish.
- The skill's own install-switch, research and report rules are otherwise
  unchanged.

## Decisions
- **Absolute means local.** Server paths in a catalogue are always relative
  to the server root, so the path's form tells the two apart with no
  probing and no ambiguity against a same-named relative file.
- **`inspect` beside `fetch`.** Reusing the script's type and generator
  detection keeps one detector for both sources, and a separate subcommand
  keeps the credentials path out of local inspection entirely.
